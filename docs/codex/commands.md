# Codex CLI 命令

在 Codex 输入框里输入 `/` 打开命令菜单，继续输入关键词过滤（例如 `/goal`），按回车执行，按 `Esc` 取消。本页讲这些 `/` 命令；在系统终端里运行的 `codex exec`、`codex fork`、`codex mcp` 看 [进阶用法](/codex/advanced)。

`/` 命令是控制命令，不是聊天内容。要让 Codex 在文档里写出 `/goal` 这几个字，明确说“把 `/goal` 作为文本写进文档”。

## 新手先用这几个

| 命令 | 什么时候用 |
| --- | --- |
| `/goal` | 多步任务一开始就用，写清目标、范围和完成标准，防止 Codex 跑偏 |
| `/review` | 改完代码或文档、提交前，让 Codex 找 bug、遗漏和风险 |
| `/memories` | 长期使用时开启，让 Codex 记住你的稳定偏好和工作习惯 |
| `/skills` | 熟练后经常用，写文档、查资料、调试、审查、测试时切到对应的专门流程 |
| `/resume` | 网络中断、误关终端、退出后重进、切换端点或模型后，回到原任务继续，不用重新解释背景 |
| `/model` | 按任务换模型：重要任务用 `gpt-6-astra`，普通工作用 `gpt-6.1-sol`，简单操作用 `gpt-6-luna` |

## `/goal`：给长任务设完成标准

```text
/goal 修复登录页提交后不显示错误提示的问题。范围只包括 src/pages/login 和相关测试。完成标准是相关测试通过，并说明改动和未验证项。
```

目标要写清任务对象、允许范围和验收方式。`/goal 优化项目` 这种写法太宽，Codex 判断不了什么时候算完成。

| 写法 | 作用 |
| --- | --- |
| `/goal` | 查看当前目标 |
| `/goal pause` | 暂停目标 |
| `/goal resume` | 恢复目标 |
| `/goal clear` | 清除目标 |

## `/review`：审查当前改动

直接输入 `/review`，或加上范围和重点：

```text
/review 只审查 docs/codex 下面的文档改动，重点看链接是否失效、事实不确定却写成确定。
```

文档改完让它查链接、结构和重复；代码改完让它查 bug、边界条件和缺少的测试；提交前让它查有没有混进无关改动。审查不能代替测试，审查后仍要运行项目的构建或测试命令。

## `/fork` 和 `/resume`：分叉与恢复会话

`/fork` 在当前上下文上开一条新方向，适合已经读完代码、想换一种方案试：

```text
/fork 基于当前分析，只写测试计划，不修改代码。
```

`/resume` 回到之前保存的会话。

| 你在哪里 | 用什么 |
| --- | --- |
| 已经在 Codex 输入框里 | `/fork`、`/resume` |
| 还在系统终端，没进入 Codex | `codex fork`、`codex resume`；`codex fork --last` 直接分叉最近一次会话 |

## `/model`、`/fast` 和 `/permissions`

| 场景 | 模型 |
| --- | --- |
| 重要任务、复杂重构、疑难 bug，或回答质量不稳定 | `gpt-6-astra` |
| 普通代码修改、文档整理、日常工作 | `gpt-6.1-sol` |
| 简单问答、小改动、低风险操作 | `gpt-6-luna` |

`/model` 里同时可以调整 reasoning effort。

`/fast` 开启 1.5 倍速度模式，紧急任务、赶时间时使用；会增加 50% 价格，价格变化可在使用记录中确认。复杂方案和高风险改动不要只追求快。

`/permissions` 选择 Codex 能做什么：只解释代码时保持只读；要改文件时选能写当前工作区的模式；只在明确知道风险、环境已隔离时才放宽权限。

## `/compact`：长会话接近上限

先让 Codex 总结状态，再压缩：

```text
请先总结当前任务状态：已完成什么、还没做什么、关键文件和验证命令是什么。
```

然后输入 `/compact`。压缩后适合继续同一个任务，但细节不会全部保留。

## `/plan`：先讨论，不改文件

需求不清、涉及多文件多模块、只想讨论或做风险评估时，用 `/plan` 切到 Plan mode，Codex 只出方案不动文件。已经明确要实现时，直接描述任务和验收标准，不用每次进 Plan mode。

## `/memories` 和 `/init`：长期规则放哪里

| 命令 | 保存什么 | 例子 |
| --- | --- | --- |
| `/memories` | 跨项目都稳定的偏好 | 回复风格、常用语言、长期工作习惯 |
| `/init` | 只属于当前项目的规则，写进 `AGENTS.md` | “修改代码后必须运行 `npm run build`” |

两者不要混用。Codex 总是按某种方式做事、找不到原因时，检查 `/memories`、`/skills`、`/hooks` 和 `AGENTS.md`。

## 其他命令

| 命令 | 什么时候用 |
| --- | --- |
| `/status` | 不确定当前模型、目录、权限、目标或 token 消耗时先看这里 |
| `/mention` | 指定让 Codex 读某个文件，比笼统说“看一下项目”更稳定、更省上下文 |
| `/ide` | 正在编辑某个文件或选中一段代码时，把 IDE 当前位置带给 Codex |
| `/copy` | 把最近一次回复复制成 Markdown，贴到文档、Issue、PR 或群聊 |
| `/raw` | 终端里复制大段输出不方便时，切换 raw scrollback 模式 |
| `/diff` | 提交前核对具体文件差异，包括未跟踪文件 |
| `/hooks` | Codex 行为被自动规则影响，或要控制工具调用、命令、文件编辑流程时 |
| `/import` | 从 Claude Code 迁移过来，导入 setup、项目和最近聊天 |
| `/approve` | 自动审查拦住了一次操作，你确认重试安全时批准这一次 |
| `/experimental` | 开关实验功能，只在明确知道影响、能接受不稳定时使用 |
| `/archive` | 任务结束但以后可能翻记录时，归档当前会话并退出 |
| `/delete` | 永久删除当前会话并退出，删除后无法恢复；不确定时用 `/archive` |
| `/title` | 同时开多个 Codex 窗口时，设置终端标题区分任务 |
| `/statusline` | 想在底部直接看到模型、目录、目标、消耗时，设置状态栏 |
| `/keymap` | 终端快捷键冲突、方向键或复制操作不顺手时重新映射 |
| `/vim` | 习惯 Vim 输入时开启 |
| `/theme` | 代码颜色看不清时换语法高亮主题 |
