# Codex 批量生图

需要一次测试多组提示词、对比效果并多轮修改时，让 Codex 把生图做成一个项目：整理需求、写提示词、批量生成、记录结果、复盘下一轮。只生成几张图，直接用 [安装生图工具](/image-video-group-image) 或 [无限画布](/images/infinite-canvas)。

一个生图任务建一个文件夹，下面的提示词都让 Codex 读取这个文件夹里的资料：

```text
生图项目/
  需求说明.md
  提示词.md
  结果记录.md
  输出图片/
```

## 1. 整理需求

```text
请根据当前对话和当前文件夹里的资料，整理一份图片需求说明，保存为 `需求说明.md`。

要求：
1. 不要直接开始生图。
2. 拆成：用途、目标受众、图片数量、尺寸比例、画面主体、风格方向、色彩倾向、必须出现的元素、必须避免的元素、文字区域、交付格式。
3. 资料不足时，只列出必须向我补问的问题。
4. 最后给一版可以直接拿去写提示词的简洁总结。
```

## 2. 写提示词方案

```text
请根据当前文件夹里的 `需求说明.md`，生成 6 组生图提示词，保存为 `提示词.md`。

要求：
1. 每组方向明显不同，不要只换几个形容词。
2. 每组写清：画面主体、构图、环境、光线、色彩、材质、镜头感、风格、文字区域、避免事项。
3. 画面里要出现中文文字时，单独写出文字内容。
4. 输出表格，列为：方案名、适合用途、提示词、避免事项、适合尺寸。
```

## 3. 批量生成

```text
请根据当前文件夹里的 `需求说明.md` 和 `提示词.md`，写一个批量生图测试脚本。

要求：
1. 生成 6 到 12 条测试任务，每条只改一个主要变量，例如构图、背景、光线、色彩、风格、材质、文字区域。
2. 任务写进 `批量提示词.json`，字段：编号、方向、测试目的、提示词、尺寸、输出文件名。
3. 调用 POST https://api.myautoapi.com/v1/images/generations，模型用 gpt-image-2.6-flare，请求体包含 model、prompt、size。
4. API Key 从环境变量 `MYAUTOAPI_API_KEY` 读取，不写进脚本。
5. 不安装新依赖；缺少必要工具时先告诉我缺什么，等我确认。
6. 图片保存到 `输出图片/`，每条结果追加写入 `结果记录.md`；单张失败时记录错误信息，继续下一张。
7. 默认顺序生成，并发最多 2 张。
```

接口和参数看 [生图 API](/images/image-generation) 和 [生图参数汇总](/images/params)。

在无限画布里手动生成时，把第 3 步换成：

```text
请根据当前文件夹里的 `提示词.md`，整理 3 个主方向、每个方向 3 条提示词（从保守到大胆），每条配一个短标题和图片文件名，例如 01-product-closeup-a.png，最后给一份结果记录表模板。
```

## 4. 复盘结果

```text
请复盘当前文件夹里的这批图片，读取图片、`结果记录.md`、`批量提示词.json` 和 `提示词.md`。

输出：
1. 最接近目标的图片编号。
2. 每张图的优点和问题。
3. 问题归因：主体、构图、光线、风格、文字区域、比例，还是提示词不清楚。
4. 下一轮保留什么、修改什么。
5. 3 条优化后的提示词。
```

## 5. 整理项目文档

项目要持续几轮时，最后让 Codex 留一份可复用的总结：

```text
请根据当前文件夹里的需求说明、提示词、结果记录和图片文件名，整理一份 `项目总结.md`。

包含：项目目标、风格规范、提示词模板、文件命名规则、复盘结论、下一步计划。已验证有效的提示词放进“可复用提示词”，效果不好的方向放进“避免方向”并写明原因。
```

## 提示词写法

| 模块 | 写什么 |
| --- | --- |
| 主体 | 画面里最重要的对象 |
| 场景 | 背景、环境和使用场景 |
| 构图 | 近景或远景、居中、留白、比例 |
| 光线 | 自然光、棚拍、逆光、柔光 |
| 色彩 | 品牌色和情绪 |
| 材质 | 产品、服装、建筑或道具的细节 |
| 风格 | 写实、插画、摄影、海报、电商图 |
| 文字区域 | 后期要加字时，提前留出干净区域 |
| 避免事项 | 不要出现的元素、错误文字、杂乱背景 |

每轮只改 1 到 2 个变量，才能看出是哪一项带来了变化。
