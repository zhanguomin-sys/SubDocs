公开资料只写 1M 的模型采用 1,000,000 token 配置，不向上猜测二进制窗口值；DeepSeek、MiMo 按各自官方 Codex 目录明确给出的 1,048,576 设置。有效输入窗口设为 95%，自动压缩阈值留空，由 Codex 依据窗口计算。此处的窗口不是最大输出 token。

MiniMax M3 的资料说明 `thinking` 的 enabled、adaptive、disabled，未提供可用于本版的准确 `reasoning_effort` 档位，因此不套用 M3.1 的档位；小写 `minimax-m3` 是本项目确定的中转站请求 ID，尚未通过正式中转站列表核对。Kimi 使用模型作者当前文档的三个档位，不套用某些托管渠道仅开放 max 的限制。

Codex 的输入目录只声明文本与图片，模型支持视频或文件不表示应在这里新增 Codex 不识别的枚举。GLM-5.3 和 Hy4 保留文本输入，Flash 与 Kimi/MiniMax 的原生视觉能力分别声明。

DeepSeek 使用官方 Codex 目录中的 freeform 补丁工具、并行工具、verbosity 与原图细节设置。MiMo 两款按小米官方目录使用 freeform 补丁工具、原图细节和 `use_responses_lite=true`，推理默认值为 low，提供 none、low、medium、high；官方说明非 lite 模式不接受 custom 工具。构建器保留这两项模型专属字段，其他模型维持原默认值。

其余模型没有声明原生 freeform 工具；`apply_patch_tool_type` 使用 `null`，不写 Codex 不接受的 `function` 枚举。Qwen 开放并行工具调用，MiMo 按官方目录使用串行；其余没有在本项目核实原生并行的模型也使用串行工具设定，这是 Codex 工具调度选择，不宣称上游不具备并行能力。

摘要参数与推理档位分别处理：新字段 `supports_reasoning_summary_parameter=false` 避免额外发送摘要参数；旧字段在有推理档位的模型上保留 true，因为旧 Codex 用它控制整个 reasoning 请求对象。MiniMax 不声明推理档位。`default_reasoning_summary=none`。

模型指令由本项目编写，不复制 GPT 的专用系统提示词。`shell_command`、目录必填字段、工具枚举及旧 `base_instructions` 与新指令结构的接受情况，按 [Codex 0.162.1 协议源码](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/protocol/src/openai_models.rs)整理，并实际用该后端加载全部目录校验。GPT 与用户模型的未知字段原样保存在输出目录，不做此类重建。
