## 安装链路系统审查与集中修复

此前验收把开发环境成功扩大成了用户安装可用的结论，随后又把用户每次反馈当成下一项测试输入；这是验收范围不足。本轮先由两名代理分别审查执行入口和配置事务，集中处理确定问题后再发布。`bas` 不存在只说明命令尚未执行，不能据此判断 Bash 不可用。

| 已复现的问题 | 集中处理 |
| --- | --- |
| 合法 Node 模块默认设置让导入跳过、退出 0，随后错误关闭客户端 | 明确 CommonJS 模式；关闭前同时检查退出状态和完整导入结果 |
| BOM 紧接首个配置段时被插入正文，原合法 TOML 被写坏 | BOM 保持首位，按去除 BOM 后的正文重新计算位置；真实后端核对导入前后均能加载 |
| 目录外的合法默认模型、复核模型别名阻断导入 | 保留原值，移除目录成员门槛，不猜测别名元数据 |
| 读取目录后、建立事务快照前出现修改，新增模型会丢失 | 记录初始配置、输出目录、管理记录及独立原目录；暂存前和提交前核对 |
| 提交后的失败恢复覆盖 App 刚保存的设置 | 恢复前检查三文件；外改、删除或不可读时保留当前整组及备份，无冲突才恢复 |
| Windows 丢弃 stderr，macOS 将 stderr 接到空设备 | 使用受控错误类别、字段白名单、数字位置、操作路径和退出码，不输出原始异常或配置 |
| `node` 不合格时不尝试可用的 `nodejs` | 逐个验证候选 |
| macOS 只有 CLI 时找不到已安装 Codex | App 后端优先，再查找 PATH 中的 CLI |
| 相对 PATH 在子进程更换工作目录后失效 | 只对子进程按调用目录绝对化 PATH，保留查找语义 |

同时逐项核对所用命令，保留必要动作：
