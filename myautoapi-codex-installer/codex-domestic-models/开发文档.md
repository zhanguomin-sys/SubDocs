# Codex 国产模型导入脚本开发文档

状态：开发已实施；隔离测试及独立代码审查记录见本目录，桌面实机验收尚待完成。
日期：2026-10-18。

本脚本面向已安装 Codex 的用户，按 DeepSeek 官方方法写入本地模型目录，并保留原有 GPT，让两类模型并列可选。官方账号、任意服务名称和自定义端点均可导入；脚本只修改用户目录 `config.toml` 的模型目录指向及桌面推理档位，保留默认模型、服务名称、接口、Key 和其他配置。[参考方法](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/codex/)

## 1. 子项目和交付文件

子项目名称为 `codex-domestic-models`，在 `myautoapi-codex-installer/codex-domestic-models/` 内开发，源码、模型设定和测试都留在本目录。它负责国产模型导入，与上级原有 GPT 一键接入脚本分别维护。交付 `install/codex-models.ps1` 与 `install/codex-models.sh`，分别用于 Windows 和 Linux/macOS；`.sh` 用系统 `sh` 执行并自动识别系统，不增加另一条 Linux 发布入口。

完成后由开发者手动把发布脚本迁移到上级 `myautoapi-codex-installer/install/`，再迁移到 `docs/public/install/`。使用新的脚本文件名，原一键配置入口继续保留；子项目保留完整源码。

## 2. 软件设定中的导入名单

软件内部只维护一份模型名单和元数据，两个平台使用相同数据。名单由维护者写定，用户运行时直接导入。

| GLM Flash | `glm-5.3-flash` |

| 千问 Flash | `qwen3.8-flash` |

| 小米 MiMo Pro | `mimo-v2.6-pro` |

使用完整、精确的请求 ID，不从产品名称拼接，不使用通配符，不自动转换大小写。DeepSeek V4.1 Flash 的请求 ID 已由官方与本站价格数据核对为 `deepseek-flash`；额外的 `deepseek-v4.1-flash-1017` 条目按上游指定 ID 和显示名维护，能力字段见[元数据来源](元数据来源.md)。MiniMax 的小写 ID 尚待核对中转站正式模型配置，不能当作已验证结果。

## 3. 脚本执行流程

1. 读取 `CODEX_HOME`，未设置时使用用户的 `.codex`；读取 `config.toml` 和原有模型目录，没有配置目录时创建。
2. 保留原有 GPT 和其他用户模型。Windows 从本地缓存和内嵌 GPT 元数据补缺；Linux/macOS 从已有后端补缺。加入软件设定中的国产模型。
3. 在用户配置目录内暂存三个目标文件。Windows 只做本地 TOML/JSON 和元数据校验；Linux/macOS 继续用私有最小配置调用已有后端。
4. 核对读取以来输入文件未变，备份原文件，写入 `myautoapi-models.json`、管理记录和两项目标配置。
5. 读回核对最终模型目录与三个文件；无外部修改时失败恢复原状态，存在外部修改时保留当前内容及备份。
6. Windows 不查找、启动或复制可执行文件；写入成功后使用上级安装脚本的进程函数关闭 ChatGPT/Codex。Linux/macOS 保留原来的成功后关闭逻辑。重新打开后新建任务选择模型。

`myautoapi-models.json` 就是保存全部模型元数据的文件，`model_catalog_json` 只是指向它。Windows 默认放在 `C:\Users\你的用户名\.codex`，Linux/macOS 默认放在 `~/.codex`；使用自定义配置目录时采用实际目录。

本地目录会替换内置目录，所以必须包含 GPT，不能只写国产模型。[官方目录说明](https://learn.chatgpt.com/docs/enterprise/roll-out-a-gateway)

## 4. GPT 共存和元数据

原有有效目录中的 GPT 和其他用户模型保留完整对象，同 ID 的原有条目优先。Windows 其次读取 `CODEX_HOME/models_cache.json` 的有效 GPT 对象，最后用脚本内嵌的完整 GPT 元数据快照补缺；缓存不存在、格式旧或不可读时仍可导入。快照位于 `src/gpt-catalog.json`，来源为开发验证用 Codex 0.162.1 的公开内置目录，包含完整模型字段和指令，不能用猜测的模型名代替。Windows 用户运行时不导出目录，不依赖 CLI、App 安装位置、可执行文件或网络访问。

Linux/macOS 仍通过本机后端取得内置目录；macOS 优先采用 App 后端，Linux 未取得运行中 App 后端时使用现有 `codex` 命令。原有完整服务配置加载失败时可用后端内置目录补缺，不改变用户服务配置。

原有默认模型与复核模型可以是目录外的自定义别名，保留配置即可，不要求它们必须出现在目录，不猜测其完整元数据。

用户当前默认模型、复核模型和已有自定义模型都应保留。每个国产模型按官方资料整理完整元数据，至少核对：

- 准确的模型 ID、显示名称、菜单可见性和排序。
- 上下文长度、有效窗口及压缩设置。
- 默认推理档位和可选档位。
- 文本、图片输入能力。
- 补丁工具格式、并行调用及其他能力声明。
- 模型指令和目录格式要求的字段。

不能复制 GPT 模板后只改名字，不能对所有模型启用同一套能力。发布脚本内嵌本版国产模型数据，支持直接远程执行，不要求另外下载配置文件。Windows/macOS 使用系统运行环境；Linux 使用已有 Node.js 16+，缺少时退出并说明，不自动安装依赖。Linux/macOS 共用模型处理核心。

桌面推理菜单参照 DeepSeek 官方方法配置 `[desktop].enabled-reasoning-efforts`。已有该字段时，以其中档位为基础；没有时，以目标 App 的 GPT 原有可选档位为基础。两种情况都加入本版国产模型所需档位并去重，保留默认推理强度及其他桌面设置，不创建重复的 `[desktop]` 段。每个模型实际可用的档位仍由自己的元数据声明，菜单配置不代表所有模型支持所有档位。

## 5. 保留配置和处理失败

配置只更新根级 `model_catalog_json` 和 `[desktop]` 中必要的 `enabled-reasoning-efforts`，不整份覆盖 `config.toml`，不修改 `auth.json`，不输出 Key。根级字段放在第一个 TOML 配置段之前，桌面字段写入原有桌面段；正确处理已有字段、路径转义和文件编码。

没有配置时只创建上述两项，不写入 `model_provider`、`model_providers`、`base_url`、默认模型或认证信息。原有服务名即使未定义，也保持原样；模型导入不修补服务接入。Windows 在本地解析暂存配置及模型 JSON，提交后读回模型 JSON 并核对完整元数据。Linux/macOS 的校验后端在私有暂存目录加载最小配置，分别读取暂存和最终模型 JSON；不加载用户的服务、认证或指令文件。三个最终文件须与本次生成结果一致，失败时按原有文件的存在状态恢复。

配置开头的 UTF-8 BOM 保持在文件首位，再按正文计算插入位置。初读配置、输出目录、管理记录和原目录时保存原始文本；创建暂存目录前及提交前分别核对，期间有修改就停止，保留其他程序写入的新内容。

提交后失败时，先检查恢复是否会覆盖外部修改。存在冲突就保留当前三个文件和备份，明确报告冲突，不关闭软件；没有冲突时按快照恢复。不要通过恢复旧文件抹掉 App 刚保存的新设置。

解析或写入失败时保留或恢复原文件，不结束进程，不报告完成。开发和测试只写本子项目内的隔离目录，不修改个人配置，不使用 `rm`。

脚本沿用现有 Responses 接入，中转站负责转换，用户自行切分组。本项目不开发代理、缓存策略、分组管理或模型表现评测。

## 6. 写入成功后的进程处理

Windows 导入和卸载都只处理用户配置目录文件，`CodexPath` 参数只保留解析兼容，不查找或使用可执行文件。构建产物不包含后端启动或 App 查询函数；写入成功后才调用从上级脚本取得的进程检测与关闭函数。测试同时覆盖存在与不存在 CLI 的环境，结果均由文件内容决定，进程测试拦截终止操作。

Linux/macOS 直接复用上级 [Shell 脚本](../install/install.sh) 的用户筛选、自身和祖先进程排除、结束和结果报告。运行时提示成功配置后会自动关闭软件并中断运行中的任务；写入成功后执行，不自动重新启动 App。

Linux/macOS 同时核对运行器退出状态与导入完成结果，收到完整结果才进入关闭步骤。Linux 明确指定 CommonJS 模式，依次选择可用的 `node` 或 `nodejs`；后端子进程的相对 PATH 按调用目录绝对化。macOS 优先使用 App 后端，没有 App 时再查找 CLI。这些运行检查不改变用户端点或认证。

## 7. 重复运行与 App 升级

同一入口提供 `--uninstall` / `-Uninstall`，用于移除本工具导入的国产模型。只按 `myautoapi-models.managed.json` 的有效 ID 过滤固定的 `myautoapi-models.json`，保留 GPT、其他模型的完整对象及目录顶层字段，管理记录清空为 `[]`。配置文件原文、目录指向和桌面档位保留；不按备份猜测安装前状态，不修改用户另行指定的目录。记录缺失或已清空时不写文件、不关闭客户端。卸载不调用 Codex 后端，仅校验过滤前后的目录并复用写入、备份、回滚和并发修改保护；只有删除当前使用目录中的条目时才关闭客户端。

重复运行就是更新：本工具管理的国产模型按本版设定整条替换，不保留旧对象中已取消的字段；加入新增项，移除本工具已经取消的条目。首次导入遇到同 ID 的国产条目，也在备份后按本版设定更新。

GPT 和其他用户模型保留完整对象，目标 App 可取得的新条目只补缺。本次不承诺刷新全部原有 GPT 元数据。只记录上次由本工具管理的 `slug` 列表，GPT 不进入这个列表；不增加其他管理系统。

配置和目录与 DeepSeek 官方方法一样放在用户目录中，正常 App 升级后继续读取。升级本身不意味着导入失败，也不要求用户每次升级重跑脚本；文件保留的预期依据是其与 App 安装目录分离。[官方配置位置](https://learn.chatgpt.com/docs/config-file/config-advanced)

不增加自动重跑、后台程序、定时任务或升级 hook。用户主动更新时重新生成目录。固定本地目录不会自动加入未来新增的 GPT，作为该配置方式的限制说明即可，不扩展成本项目的自动同步功能。

再次运行原一键配置脚本会覆盖 `config.toml` 并移除目录指向，此时重新运行导入脚本即可恢复。

## 8. 交付检查

开发者完成以下检查即可：

1. 桌面 App 正确显示 GPT 和确定的 11 个国产条目，选中的条目使用准确请求 ID。
2. 元数据完整，桌面推理档位补齐且原有 GPT 档位保留，选项与输入能力符合设定，默认模型和原配置保留。
3. 重复运行确实更新，模型不重复，用户其他模型不丢失。
4. 失败保留原文件；Windows 全程只读写文件，Linux/macOS 成功后进程处理与原脚本一致。
5. 做一次正常 App 升级检查，确认原配置和目录继续读取，不把所有未来版本的假设变成复杂兼容系统。
6. 发布脚本与子项目交付版本一致，再由开发者手动迁移发布。

源码、生成的两个发布脚本及隔离测试已在本子项目实现。真实桌面升级尚未执行；此前的详细源码讨论仅作为备查，不增加到开发流程中。


## 7. Windows 精简重构（2026-10-16，取代第 3–5 节中与下列冲突的 Windows 部分）

- 配置修改：逐条语句读取，只替换或插入 `model_catalog_json` 与 `[desktop].enabled-reasoning-efforts`，按语句序号编辑，不排序、不做偏移位移；写前核对新配置能解析且两项取值正确。`desktop` 内联表、profile 另设目录、重复 `desktop` 段仍拒绝写入。
- 官方模型：内嵌快照加 `models_cache.json`，不限 `gpt-` 前缀，隐藏条目原样保留；缓存版本不低于快照才覆盖，否则只补缺；已有目录中的官方条目由缓存刷新，用户自定义条目保留；从不丢弃已有条目。已有目录与缓存条目只做轻量形状检查，是否可加载交给 Codex。
- 写入：临时文件、校验、备份、移动，`config.toml` 最后；不保留事务、冲突回滚与读回比对。管理记录只是归属提示，损坏时回落到内置国产清单。
- 卸载：按管理记录和内置清单过滤目录，不动 `config.toml`。
- 未知桌面推理档位原样保留，不再因未知值中止导入。

## 8. Codex 更新后什么时候需要维护者介入

脚本把官方模型来自 Codex 自己的缓存和内嵌快照，普通更新不需要改脚本。下面分两类。

### 普通更新：不用改，用户不用管

- 版本号小幅变化、修复类更新，已导入的目录继续可用（新增字段有默认值）。
- GPT 新增、下架或元数据微调：用户重新运行同一命令，缓存里的官方条目会刷新目录；没有重新运行时旧目录照常工作，只是看不到新模型。
- 新增推理档位名称：脚本原样保留未知档位，不会中止导入。

### 大更新：必须由维护者修改并重新发布

满足下列任一条，就按本节检查表处理。

| 触发情况 | 现象 | 要改什么 |
| --- | --- | --- |
| 模型目录格式变化：新增必填字段、重命名或删除字段、枚举取值变化 | 导入后 Codex 启动报错或模型菜单为空；`codex debug models` 加载失败 | 改 `build.py` 里国产模型的元数据，重新导出并更新 `src/gpt-catalog.json` |
| `model_catalog_json` 改名、移动，或改成与内置目录合并（不再整体替换） | 国产模型不出现，或 GPT 重复出现 | 改 `src/core.ps1`、`src/core.js` 的写入字段；合并后可去掉官方模型内嵌逻辑 |
| `[desktop].enabled-reasoning-efforts` 改名、移位，或推理菜单改为别的配置 | 模型能选但推理档位菜单缺项 | 改两端写入的桌面档位字段 |
| 缓存 `models_cache.json` 改名、换目录，或 `models`、`client_version` 字段变化 | 脚本不报错，但提示“GPT 列表来自内置快照”，新模型不会刷新 | 改缓存读取逻辑，同时更新快照 |
| 内置目录新增或删除官方条目（尤其隐藏条目，如 `codex-auto-review`） | 无缓存的用户目录里缺这些条目，相关功能异常 | 重新导出快照并核对条目数 |
| 字段含义变化（如 0.134 到 0.162 的推理摘要字段） | 能加载但请求行为不对 | 按[升级兼容性讨论](升级兼容性讨论.md)逐字段核对，改国产模型元数据 |
| 桌面端或命令行的进程名、安装方式变化 | 导入后提示“未能自动关闭”或没关到客户端 | 先改 `myautoapi-codex-installer/install/install.ps1` 和 `install.sh`，再重新构建本脚本（进程函数从那里原样取出） |
| 默认配置目录或 `CODEX_HOME` 规则变化 | 文件写到了 Codex 不读取的位置 | 改默认目录判断 |
| 配置文件格式不再是 TOML，或同名字段挪到别的表 | 导入报“TOML 配置行无效”之类，或字段写了不生效 | 改 `src/core.ps1` 的字段识别 |

### 每次 Codex 发布后的检查

1. 用新版本运行 `codex debug models --bundled`，与 `src/gpt-catalog.json` 比较：条目 ID 集合、每个条目的字段名是否一致。
2. 新建隔离的 `CODEX_HOME`，对生成的 `myautoapi-models.json` 运行 `codex debug models`，确认全部模型加载成功。
3. 运行 `python3 tests/test_models.py`，其中包含真实 Codex 加载检查。
4. 没有差异就不用动；有差异按上表修改，然后同步更新 `src/gpt-catalog.json` 和 `build.py` 里的 `OFFICIAL_SNAPSHOT_VERSION`。
5. 重新构建，按顺序同步到上级安装目录和站点发布目录，并核对线上文件与仓库一致。
