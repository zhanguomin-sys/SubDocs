# V0.3 实施记录：专门画图分组 Key 与可控更新

## 目标

V0.3 把图片工具使用的 Key 从 V0.2 的单一 `auth.json` 来源切换为“专门画图分组”的 Key。用户运行独立安装入口后粘贴一次，工具把 Key 保存到自己的工具目录；Codex AI、Skill 和安装提示不读取 `auth.json`。

V0.3 同时完成用户主动触发的可控更新。用户明确对 Codex 说“更新生图工具”后，Codex 在当前任务中自行完成检查、下载、安装和验证；这不是系统后台服务或定时更新。后续仍使用安装状态 `0.3.0` 和 `V0.3-rN` 发布修订，不升级为 `0.4.0`。

## 已实现的交互

- 独立安装器提示用户粘贴“专门画图分组”的 Key，输入内容正常显示。
- 提示明确说明：安装器无法分辨 Key 是否复制错误，用户必须自行核对。
- 组合入口使用隐藏的 `--integrated` 模式：首次确认和重复 Key 确认都采用 `[Y/n]`，直接回车或输入 `Y` 继续，输入 `N` 退出当前生图安装。
- 组合入口只在两个 Key 完全相同时提醒，不自行判断分组归属。
- 用户退出生图安装时不报告错误，不回滚已经完成的基础 Codex 配置。

## 文件与来源

- `api-key`：工具目录内的专门画图分组 Key。
- `key-source`：当前来源标记，V0.3 默认值为 `dedicated-image-key`。
- `auth-json`：保留为工具内部兼容模式，不在 Skill、安装器主路径或客户文档中主动展示。
- Key 不写入 `install-manifest.json`、日志或临时磁盘备份；安装事务失败时恢复原 Key 状态。
- 使用操作系统默认文件权限，不强制 `0600`，不额外修改 Windows ACL。

## 版本与发布

- 安装状态版本：`0.3.0`。
- 当前发布修订：`v0.3-r5`。
- 发布目标只有 Windows x64 和 Apple Silicon Mac。
- 发布脚本按系统和架构只下载对应的一个程序，并显示百分比进度。
- `v0.3-r3` 起，工具默认使用当前工作目录的 `images`；Skill 有项目时明确传入项目 `images`，无项目时明确传入桌面 `images`，不再使用 `$CODEX_HOME/images`。
- `v0.3-r3` 起，Skill 固定为单个前台命令、等待同一命令、直接读取 stdout 和打开 `output_file`，不再用额外命令搜索工具、检查目录、轮询进程或扫描结果文件。
- `v0.3-r4` 起，Skill 在调用前申请范围受限、可复用的联网许可，所有用户可见进度使用中文，并在命令退出前持续等待同一执行会话。
- `v0.3-r5` 起，公网只保留 Windows、Mac 两个安装入口；Windows 提示词通过单引号 here-string 变量传入工具，不再直接拼接到 PowerShell 命令文本。

## 已实现的 V0.3 更新流程

- 把稳定的 `install.ps1` 和 `install.sh` 同时作为安装、修复和更新入口；不新增常驻更新进程。
- 在全局规则中加入更新触发词和固定入口。只有用户明确要求“更新生图工具”时，Codex 才执行更新，不在启动、生图或空闲时检查。
- Codex 接手后自行完成当前任务，不要求用户再次粘贴命令；执行过程使用中文并等待更新命令真正退出后再报告结果。
- 增加独立发布修订号并写入安装状态或托管文件，使本地能够区分同一 `0.3.0` 下的 `V0.3-r3`、`V0.3-r4` 等修订。
- 在线入口先比较本地与在线修订。版本相同时直接报告已经是最新版，不下载原生程序；版本不同时只下载当前平台的一个程序。
- 更新前校验来源和 SHA-256，使用临时文件、事务写入和失败回滚；不创建后台服务、计划任务或开机启动项。
- 工具目录已有非空 `api-key` 时必须保留原文件，不读取内容、不覆盖、不再次提示输入。只有首次安装或 Key 缺失、为空时进入专门 Key 输入流程。
- 更新成功后核对工具、Skill、全局规则和发布修订，再提醒用户新开 Codex 任务；离线、下载失败或校验失败时保留原版本。
- Windows 代码签名和 macOS 签名、公证暂不实现；收到真实拦截反馈后再单独评估。

## V0.3 更新验收

- 正常生图、Codex 启动和系统启动均不访问更新地址。
- 用户明确要求更新后，Codex 才访问稳定入口并自行完成流程。
- 已是最新版时只完成轻量检查，不下载 Windows 或 macOS 原生程序。
- Windows 只下载 Windows x64，Apple Silicon Mac 只下载 Darwin arm64。
- 已有专门 Key 的更新全程不出现 Key 输入提示，更新前后 Key 文件保持不变。
- 哈希不一致、网络中断、写入失败和结果校验失败均回滚，不留下半更新状态。
- 更新过程中不读取或修改 `$CODEX_HOME/auth.json`，不把专门 Key 写入日志、清单或临时磁盘备份。

## 迁移边界

子项目与父项目使用独立 Git 仓库。每次修改安装器、正式工具、Skill、清单或 README 后，必须先在本子项目完成测试、构建和哈希更新，再由维护者手动把 Windows、Mac 两份在线安装脚本、两个平台程序和 `SHA256SUMS` 迁移到父仓库 `docs/public/install/myautoapi-imagines-tool/` 的对应版本目录。迁移完成后，父仓库另行执行站点构建、公网哈希核对和隔离 `CODEX_HOME` 安装测试。

快速开始脚本的合并入口不属于本次 V0.3 子项目交付；本次只提供供未来快速开始调用的 `--integrated` 内部模式。
