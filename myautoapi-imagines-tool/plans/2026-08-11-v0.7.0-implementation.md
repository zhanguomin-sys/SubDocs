# V0.7.0 Nano Banana 实施计划

## 目标

在 V0.6.0 的统一图片工具中加入 `nano-banana-2` 和 `nano-banana-pro`。工具负责把用户明确要求转换成 Responses 请求，解析并保存最终图片；Skill 负责调用工具和逐张显示结果，不替用户决定画面内容。

## 实施内容

- [x] 通过 `/v1/models` 确认两个正式模型 ID。
- [x] 查阅 Google 官方资料，确认生图、参考图、修图、分辨率、比例和参考图数量。
- [x] 探测 `/v1/responses` 的文本输入、`response_format` 和嵌套图片返回结构。
- [x] 为两个模型增加独立的 Responses 请求转换和 `output` 图片解析。
- [x] 支持 `generate`、`edit`、`--n`、`--resolution`、`--aspect-ratio` 和重复 `--image`。
- [x] 更新 Skill、安装规则、README、版本规划和父项目生图分组方法页。
- [x] 完成 Go、Python、Skill、发布契约测试和两个平台本地构建。
- [x] 用户确认验收后，手动迁移两个平台的公网资产并推送父仓库。

## 验收

- 两个 Banana 模型都使用 `/v1/responses`，不进入 Images 请求体。
- 规格转换保持模型 ID 不变，分辨率发送为 `512`、`1K`、`2K` 或 `4K`。
- 参考图转换为 Responses 的 `input_image`，单张输入不超过 7 MiB，最多 14 张。
- 嵌套 Data URL 或 HTTPS 图片链接能解析为有效图片，实际扩展名由文件签名决定。
- `--n 3` 返回三个平铺图片路径，Skill 明确要求在 Codex App 中逐张显示。
- 用户目录只保留最终图片，不创建请求记录或图片专属子目录。
- 两个 Banana 模型都已通过真实接口返回有效 PNG，并由工具解析、保存和打开显示。
