# MyAutoAPI 图片工具 V0.2 实施计划

> **执行状态（2026-08-09）：** 子项目内的 V0.2 安装器、Skill、安装/卸载入口、用户说明和无密钥验证已实现；Linux 临时 Codex Home 已完成真实 Skill 发现、真实 API 生图和图片查看验证。`V0.2-r1` 发布包已迁移到本站 Cloudflare Pages，公网 Linux 安装/卸载链路已验证；macOS/Windows 真实运行仍未验证。

> **当前状态：** 本文件只定义 V0.2 的实施边界和验收顺序。创建本计划时不修改 V0.1 脚本、不安装工具或 Skill、不写入任何用户目录，也不发送真实 API 请求。
>
> **边界校正：** 本项目交付给其他用户使用，不采用开发者本机的 `skill-packs` 私有管理机制。V0.2 按用户已经确认的旧目录，将独立 Skill 安装到 `$CODEX_HOME/skills/`。

> **密钥来源调整（2026-08-08）：** 工具运行时只从 `$CODEX_HOME/auth.json` 的 `OPENAI_API_KEY` 读取 API Key。安装器、Skill 和 AI 不读取、复制、展示、传递或修改 `auth.json`；安装器不再创建 `api-key`、提示输入 Key 或提供删除 Key 参数。旧版遗留的 `api-key` 保留但不再使用。

> **默认输出调整（2026-08-09，已由 V0.3-r3 取代）：** V0.2 曾把图片和运行记录写入 `$CODEX_HOME/images`。Windows Codex App 实测发现该目录可能被工作区沙箱拒绝写入；V0.3-r3 已改为有项目写项目 `images`、无项目写桌面 `images`。

## 目标

把已经完成的 V0.1 `gpt-image-2` 生图脚本整理成普通用户可以完成的一次安装流程。用户先完成 Codex 的既有鉴权配置，再运行与操作系统对应的安装入口、重新打开 Codex 后，即可直接说“画一张……”；Codex 默认调用“中转站生图” Skill 和现有生图脚本，成功后把本地图片重新显示在当前对话中。

## 已确认决定

- V0.1 的 `tool/生成图片.py` 是正式生图实现，V0.2 只安装和调用它，不重写、不替换请求与响应逻辑。
- V0.2 只支持 `gpt-image-2`，固定接口仍为 `https://api.myautoapi.com/v1/images/generations`。
- 交付形式是“独立 Skill + 一键安装器”，V0.2 不制作插件。
- Skill 技术名和目录名为 `myautoapi-image-generation`，显式调用名为 `$myautoapi-image-generation`，显示名为“中转站生图”。
- 用户提出生成、绘制、制作图片等要求时，默认走中转站生图；用户不需要说 MyAutoAPI、品牌名、模型名或 Skill 名。
- 每个生成请求只发送一次；失败后不自动重试、不换模型、不伪造结果。
- 成功后必须读取脚本摘要中的 `output_file`，使用 `view_image` 打开图片并显示在当前对话中，不能只回复路径或远程链接。
- API Key 由工具脚本从 `$CODEX_HOME/auth.json` 的 `OPENAI_API_KEY` 读取。AI 不打开、读取、复制、打印、传参、扫描或提交 `auth.json`；安装器不访问该文件。
- 文件继承当前操作系统和用户目录的正常默认权限，不强制 `0600`，不额外修改 Windows ACL。


不写入以下位置：

```text

$HOME/.agents/skills/
用户当前项目的 AGENTS.md
```

## 范围外

- 不增加 Nano Banana、Adobe、Grok Imagine、其它 GPT Image 模型或视频模型。
- 不实现图片编辑、参考图、透明背景或原生 `imagegen` 的完整能力。
- 不实现远端版本检查、自动升级、降级、跳过版本或定时检查；这些属于 V0.3。
- 不补齐 `gpt-image-2` 的完整参数矩阵；这些属于 V0.4。
- 不创建插件清单、第三方 marketplace、MCP、后台服务、网页、数据库或新的 Python 依赖。
- 不把开发机绝对路径、API Key 或未来下载地址写死到正式脚本和 Skill。
- 不修改父项目的站点页面、导航和现有多模型文档；Task 7 只允许把审核后的发布资产手动迁移到 `subdocs/docs/public/install/myautoapi-imagines-tool/`。
- 不删除子项目内必需的用户说明；正式 Skill、安装与卸载提示、失败提示和 README 使用方法都属于 V0.2 交付物。

## 发现的问题和处理结论

### 1. 当前 Skill 草案触发范围过窄

现有 `description` 只在用户提到 MyAutoAPI 或 `gpt-image-2` 时触发，不符合“所有生图默认走中转站”的决定。V0.2 必须把生图、画图、做图、生成图片、重新生成和图片对比等直接需求写入 `description`，并保持默认允许隐式调用。

### 2. 现有 Skill 示例只写了 Bash

当前 `SKILL.md` 的示例命令不能直接用于 Windows。V0.2 必须分别写清 macOS/Linux 与 Windows 的脚本定位和 Python 入口，但只保留一套行为契约，不复制两套业务规则。

### 3. `AGENTS.override.md` 可能使 `AGENTS.md` 不生效

Codex Home 中存在非空 `AGENTS.override.md` 时，它会覆盖同级 `AGENTS.md`。V0.2 不擅自修改 override 文件；安装器发现该情况时必须停止全局规则写入，保留此前所有用户文件，并明确报告原因。不能在规则实际未生效时输出“安装成功”。

### 4. 正式下载来源已确定

正式发布资产使用现有 `subdocs` GitHub 仓库和 Cloudflare Pages 链路，通过 `docs.myautoapi.com/install/myautoapi-imagines-tool/` 提供。子项目完成修改和本地门禁后，维护者必须手动制作发布包并迁移四份在线安装/卸载脚本、版本化 ZIP 和校验文件；发布脚本不得自动跨仓库修改或提交父项目。

`V0.2-rN` 的 `rN` 只区分公开分发修订，不进入 `$CODEX_HOME` 的安装状态。安装状态和冲突判断继续使用 `VERSION=0.2.0`；重跑同一 V0.2 的不同修订按当前清单修复托管文件，不属于 V0.3 的升级或降级。

### 5. 跨平台证据不完整

Linux 已有 V0.1 运行证据，macOS 和 Windows 尚未真实验证。源码审查、临时目录测试和命令语法检查不能写成真实跨平台通过；V0.2 发布状态必须按实际证据分别标注。

安装器使用 Python 3 标准库实现共同的文件处理逻辑；Bash 和 PowerShell 只负责定位可用的 Python、定位安装包根目录并启动 `安装.py`。这样可以避免 Bash 与 PowerShell 各自维护一套备份、标记和回滚逻辑。

安装器不读取、修改或复制 API Key。工具在真正请求时通过标准库 JSON 解析 `$CODEX_HOME/auth.json` 的 `OPENAI_API_KEY`，不把 Key 放进命令参数、环境变量、子进程参数、记录或终端输出。安装器不得安装 Python 或其它依赖；缺少 Python 时只说明缺少项并停止。

## 子项目内必须保留的用户说明

V0.2 不编写父级站点教程，但子项目本身必须让拿到安装包的用户知道怎样完成安装、怎样开始使用以及失败后该看什么。说明只放在以下三个位置，不新建重复教程：

- `skill-template/myautoapi-image-generation/SKILL.md`：写给 Codex 的正式调用规则。
- `installer/安装.py` 的终端输出：写给正在安装或卸载的用户，只显示当前动作、结果和下一步。
- 子项目 `README.md`：写清工具是什么、最终效果、安装入口、会修改的位置、首次使用、卸载和已验证平台。

安装器终端提示必须覆盖：

- 安装开始前说明将安装工具、Skill 和全局默认生图规则，并说明工具运行时读取现有 Codex `auth.json`，安装器不访问该文件。
- 已有文件、版本冲突或 `AGENTS.override.md` 阻断时，说明当前状态和停止原因，不输出 Key。
- 安装成功后列出已写入的非敏感路径和版本，提醒用户重新打开 Codex 或开始一个新任务。
- 首次测试只提示用户发送“画一张白底红苹果”这类短句，不让用户手工运行 Python、修改 Skill 或填写模型参数。
- 卸载前说明不会读取、修改或删除 `auth.json`。
- 失败后说明哪些文件已恢复、哪些内容没有改动以及可检查的非敏感错误，不留下“可能成功”的含糊状态。

这些提示不能扩展成安装原理、目录结构课程、插件对比或模型百科。用户完成安装所需的信息保留，作者复盘和低频背景不进入终端主路径。

## 全局规则块

V0.2 只管理下方两个标记之间的内容：

```markdown
<!-- myautoapi-image-generation:start -->
## 默认生图规则

- 用户要求生成、绘制或制作图片时，默认调用 `$myautoapi-image-generation`，不要求用户指定 MyAutoAPI、中转站、Skill 名或模型名。
- Skill 只调用已安装的 `gpt-image-2` 生图工具；调用前说明本次模型和接口，不静默更换模型或接口。
- 把用户本次完整画面要求和明确参数传给工具，不使用写死的图片描述。
- 每张图片只发送一次请求；失败后保留记录并报告真实错误，不自动重试、不换模型。
- 成功后立即使用 `view_image` 打开脚本返回的本地 `output_file`，让图片显示在当前对话中，不能只回复路径或链接。
- API Key 由工具脚本从 `$CODEX_HOME/auth.json` 的 `OPENAI_API_KEY` 读取；AI 不打开、读取、复制、展示、记录、扫描或提交 `auth.json`。
<!-- myautoapi-image-generation:end -->
```

安装器修改前必须创建同目录时间戳备份。备份只包含原 `AGENTS.md`；API Key 不进入备份。若后续步骤失败，恢复原文件并删除本次新建但尚未完成的托管文件。

## 验收命令草案

以下命令只定义后续实施完成时的本地门禁；本次计划阶段不执行：

```bash
python3 -m unittest tests/test_generate_image.py -v
python3 -m unittest tests/test_installer.py -v
<skill-creator-validator> skill-template/myautoapi-image-generation
bash -n installer/install.sh installer/uninstall.sh
git diff --check
```

其中 `<skill-creator-validator>` 指当前开发环境提供的 Skill 格式校验器，不属于项目交付内容，也不能写成某台机器的绝对路径。

Windows 在真实 PowerShell 环境执行：

```powershell
$null = [System.Management.Automation.Language.Parser]::ParseFile(
  (Resolve-Path .\installer\install.ps1),
  [ref]$null,
  [ref]$null
)
$null = [System.Management.Automation.Language.Parser]::ParseFile(
  (Resolve-Path .\installer\uninstall.ps1),
  [ref]$null,
  [ref]$null
)
```
