# MyAutoAPI 图片工具 V0.1 实施计划

> **2026-08-07 边界校正：** V0.1 只包含 `gpt-image-2` 脚本、测试和结果规则。下文 Task 4 至 Task 6 形成的 Skill 内容归入 V0.2 草案；Task 7 的安装只用于一次烟雾验证，验证后已从 Codex Home 删除，不是 V0.1 交付物。
>
> **2026-08-07 权限校正：** 后续安装器使用操作系统和当前用户目录的正常默认权限，不再强制 `0600`，也不额外重写 Windows ACL。下文 Task 7 的 `0600` 是已撤销的临时验证做法。

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在本地开发工作区完成只支持 `gpt-image-2` 的 V0.1 生图脚本、无密钥自动化测试和运行记录规则；Skill 范本单独作为 V0.2 草案保留。

**架构：** `tool/生成图片.py` 是唯一运行入口，使用 Python 标准库向固定的 MyAutoAPI 图片接口发送一次请求。脚本从 `$CODEX_HOME/tools/myautoapi-imagines-tool/api-key` 自行读取密钥，保存请求、原始响应和图片到调用方指定的结果目录；解析时优先 `b64_json`，其次只下载一次 HTTPS URL。Skill 范本只调用已安装的脚本，不读取或复制密钥，也不自行拼接 HTTP 请求。

**技术栈：** Python 3 标准库（`argparse`、`urllib`、`json`、`base64`、`unittest`）；不增加第三方依赖，不创建服务或网页。

**边界：** V0.1 固定模型为 `gpt-image-2`；默认尺寸 `1024x1024`，调用方可通过参数改尺寸、质量、输出格式和结果目录；固定 `n=1`；不自动重试，不自动升级，不安装 Skill，不支持其它模型或视频。项目目录被 `.gitignore` 忽略，当前阶段不创建提交。

## Task 2: 实现单次请求、证据保存和图片解析

**文件：**
- 新建：`myautoapi-imagines-tool/tool/生成图片.py`
- 测试：`myautoapi-imagines-tool/tests/test_generate_image.py`

- [ ] **Step 1: 实现固定运行路径与输入校验。**

  定义以下常量和函数：

  ```python
  API_URL = "https://api.myautoapi.com/v1/images/generations"
  MODEL = "gpt-image-2"

  def codex_home(environ: Mapping[str, str] | None = None) -> Path: ...
  def api_key_path(environ: Mapping[str, str] | None = None) -> Path: ...
  def load_api_key(environ: Mapping[str, str] | None = None) -> str: ...
  def build_payload(prompt: str, size: str, quality: str, output_format: str) -> dict[str, object]: ...
  ```

  `api_key_path()` 必须返回 `<CODEX_HOME>/tools/myautoapi-imagines-tool/api-key`，`CODEX_HOME` 未设置时回退 `~/.codex`。错误不能回显密钥。

- [ ] **Step 2: 实现一次 POST 和原始记录。**

  `run_generation()` 接收显式的 `output_dir`、`transport`、`downloader` 以便无网络测试；默认 transport 只发送一次 POST 到 `API_URL`，使用 `Authorization: Bearer <key>`。无论成功还是 HTTP 错误，记录目录必须包含 `request.json`、`response.raw`、`response-headers.json`、`summary.json`；可解析 JSON 时额外保存 `response.json`。不写重试循环。

- [ ] **Step 3: 实现图片来源优先级和格式检测。**

  依次扫描 `data[]`：先接受可解码的非空 `b64_json`，再接受 HTTPS `url`。URL 只下载一次，下载头保存为 `image-headers.json`。根据文件签名识别 PNG、JPEG、WebP、GIF；未知签名使用 `.bin`。至少解析 PNG 和 JPEG 的实际宽高；`summary.json` 写入 `source`、`bytes`、`format`、`dimensions`、`record_dir`、`output_file`。

- [ ] **Step 4: 运行全部单元测试并确认通过。**

  运行：

  ```bash
  python3 -m unittest myautoapi-imagines-tool/tests/test_generate_image.py -v
  ```

  预期：所有请求、密钥、Base64、URL、失败记录和泄露检查测试通过。
