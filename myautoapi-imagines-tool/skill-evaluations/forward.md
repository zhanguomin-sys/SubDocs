# Skill V0.4.1 前向演练

日期：2026-08-10

## 场景

覆盖三类请求：直接生成图片、使用参考图修改图片、同一提示词生成三张结果。演练只评估 V0.4.1 Skill，不执行命令、不联网、不读密钥。

## 结果

通过。演练回答表现为：

1. 使用已安装的 `myautoapi-imagines-tool` 原生程序；文生图执行 `generate`，参考图和修图执行 `edit --image`，固定使用 `gpt-image-2`。
2. 显式传入默认 `--size 1024x1024 --quality high`，使用 `--output-name 白色背景红苹果`，把结果直接保存到当前项目的 `images`。
3. 只执行一次调用，保留用户原始画面描述，不增加风格、元素或负面提示词。尺寸和质量只按用户要求转换；没有要求时使用默认值。
4. 单图只解析 stdout 的 `output_file`；多图只解析 `output_files`，按顺序对每个文件调用图片查看工具。三张结果必须全部显示，不能只回复路径。
5. 失败时只报告脱敏错误，停止且不重试、不换模型、不伪造结果；失败不在用户目录留下请求、响应或摘要文件。
6. 不读取、输出、传递或扫描 API Key；不使用 `curl`、SDK 或直接 HTTP；不安装或修改工具。
7. 沙箱不允许工具联网时，调用前为原生工具的 `generate` 子命令申请范围受限、可复用的联网许可，不先执行一个注定失败的请求，也不要求完全访问。
8. 所有用户可见提示使用中文；命令仍运行时继续等待同一执行会话，不提前结束或声称图片稍后自动显示。
9. 用户要求 1K、2K、4K、横图、竖图、方图、自动尺寸或质量档位时，使用 Skill 中经过真实接口验证的参数建议；用户给出其它精确尺寸时遵守工具边界校验。
10. 同一提示词要求三张结果时只执行一次 `generate --n 3` 前台命令；中转站忽略 `n` 时由原生程序在命令内部补齐，Skill 不追加命令。

## 与基线的差异

基线中的四个缺口均已消除：默认参数明确、结果路径有唯一来源、成功后必须查看图片、失败后明确停止。V0.4.1 增加参考图、修图和多图结果，并把“每张都显示在当前对话”写成成功条件。Skill 仍是项目内范本，尚未安装到全局目录。
