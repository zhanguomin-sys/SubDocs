# V0.2 安装流程演练

日期：2026-08-09

> `V0.2-r1` 的 ZIP、Python 安装器和公网验证保留为历史记录。Windows 实机验证证明 Codex App 不保证提供 Python，因此 `r1` 不再满足一键安装要求。`V0.2-r2` 首次发布原生程序，`V0.2-r3` 将范围收缩为 Windows x64 和 Apple Silicon Mac。

## V0.2-r3 无运行环境依赖验证

- 当前发布范围收缩为 Windows x64、Apple Silicon Mac 两个原生程序；安装入口只下载当前系统对应的一个程序。
- Go 无密钥测试覆盖安装、重复安装、旧 Python 工具迁移、卸载、路径冲突、Base64 图片、HTTPS URL 回退、失败记录和密钥脱敏。
- 开发阶段曾用 Linux 交叉构建验证原生安装逻辑；Linux 文件不再生成或发布。
- `python3 release/build_release.py` 只生成两个程序和两个 SHA-256，并会删除同版本目录中的其它平台旧文件。
- Windows 和 macOS 尚无 `r3` 真实运行证据；Windows 最终验证由用户在真实机器执行公网 PowerShell 命令完成。

## 验证范围

安装器契约场景只使用项目内安装包、临时 `CODEX_HOME` 和假的 `auth.json`，不读取真实密钥，也不写入开发机的默认 Codex Home。另有一次获得授权的 Linux 真实链路验证使用 `/home/ss/software/codex-all/test_one/`，工具运行时读取其现有认证并发送一次真实生图请求；AI 和安装器均未读取或展示认证内容。验证目标是确认安装器把同一套工具、Skill 和全局规则放到用户确认的旧目录：

- `tools/myautoapi-imagines-tool/`
- `skills/myautoapi-image-generation/`
- `AGENTS.md`

## 已通过场景

1. 第一次安装会创建工具、Skill、清单、`VERSION` 和全局规则；安装器不读取、修改、复制或要求输入 API Key。
2. `CODEX_HOME` 已设置和未设置两种路径都落到对应 Codex Home；测试使用含空格和中文的临时目录。
3. 相同版本完整安装不重复追加规则，也不访问 `auth.json`。
4. 托管脚本或 Skill 文件损坏时可修复，`auth.json` 保持不变。
5. 目标目录无法确认归属、版本不同、规则标记破损或非空 `AGENTS.override.md` 时停止，不覆盖用户文件。
6. 安装中途模拟失败后恢复原 `AGENTS.md`，不留下半个工具、Skill 或临时文件，也不访问 `auth.json`。
7. 卸载删除托管工具、Skill 和规则块，不读取、修改或删除 `auth.json`；旧版遗留的 `api-key` 保留但不再使用。
8. Skill 静态契约确认：用户不说品牌、模型或 Skill 名时，生图请求仍进入固定 `gpt-image-2` 流程；成功结果必须使用 `output_file` 查看，失败不重试。

go test ./...
ok  myautoapi-imagines-tool

python3 /home/ss/.codex/skills/.system/skill-creator/scripts/quick_validate.py \
  skill-template/myautoapi-image-generation

bash -n installer/install.sh installer/uninstall.sh release/install.sh
python3 -m py_compile installer/安装.py release/build_package.py

当前环境没有 `pwsh`，因此 PowerShell 入口只完成源码审查，尚无 Windows 语法和运行证据。macOS 也尚未真实运行验证。后续新增真实 API 测试场景仍需逐次取得授权，本次只执行了上方记录的一次请求。
